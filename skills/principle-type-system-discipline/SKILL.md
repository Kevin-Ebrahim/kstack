# Type System Discipline

Make the compiler reject impossible states, mismatched primitives, and unhandled variants. Prefer defining errors and special cases out of existence over proliferating handlers. For TypeScript syntax, see [typescript-best-practices](../typescript-best-practices/SKILL.md). Follow the language's idioms and the repository's established types and validation system; avoid adding wrappers that solve no demonstrated problem.

- **Brand semantic primitives.** `UserId` and `OrderId` are strings underneath but should not be interchangeable. Give each its own type, such as a branded intersection in TypeScript or a newtype elsewhere. Validate once at creation, trust the type downstream. Use distinct types where mixing values is plausible and harmful; preserve established public contracts.
- **External data is untyped until parsed.** RPC payloads, JSON, IPC messages, CLI args, config files, environment variables, database rows. Have a parse function at every boundary that turns unstructured input into the typed model. Validate at external entry points, then rely on established invariants internally; revalidate when data crosses a new trust boundary.
- **Derive types from authoritative schemas.** When a protocol buffer, OpenAPI spec, GraphQL schema, database migration, design-token file, or another file owns a shape, derive from it instead of hand-rolling a parallel type. Keep the authoritative schema and its generated types in sync through the repository's existing generation or validation checks.
