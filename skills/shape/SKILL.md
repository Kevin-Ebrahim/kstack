# Shape

Discover what should be made and how it should work. The output is a design brief, not application code.

## Resolve the important unknowns

Read the request, existing product/design context, relevant workflows, and available assets first. Ask only about missing decisions that materially change the result, grouping a few related questions at a time. A precise brief does not need a compulsory interview or repeat confirmation.

Useful questions concern the audience and situation, primary outcome, real content and evidence, states and transitions, intended fidelity, scope boundaries, and binding platform or delivery constraints. Do not ask the user to choose CSS values to stand in for a design decision.

## Form the direction

Reuse the established identity and components. When composition or interaction remains open, compare a small number of meaningful alternatives with their consequences. If a new identity is actually requested, explain the visual and structural choices directly; no missing workshop command is required.

Distinguish user-confirmed choices, evidence-backed assumptions, and unresolved decisions. If an answer is required, keep that decision pending rather than treating silence as acceptance. Continue independent analysis where useful.

## Deliver the brief

Scale the detail to the task. Cover the relevant parts of:

1. Audience, context, and primary job.
2. Desired outcome, success evidence, and product-specific content.
3. Visual authority, interaction model, hierarchy, and focal point.
4. Scope, fidelity, preserved behavior, and explicit exclusions.
5. Loading, empty, error, success, permission, and content-range states.
6. Responsive structure, inputs, feedback, and navigation.
7. Platform, accessibility, performance, localization, and delivery constraints.
8. Open choices the implementer must not silently invent.

Deliver in the requested location or in chat. Ask for a decision only when one remains necessary; never label an unconfirmed brief as approved. Stop after planning unless the overall request already includes implementation, in which case use the settled brief to continue the authorized work.
