# Figure it out

For an unusual or substantial task, design a workflow that makes progress and its evidence reviewable.

1. Ground the goal in the relevant system. State the outcome, scope, important constraints, and a concrete completion check.
2. Break the work into [verifiable units](../principle-sequence-verifiable-units/SKILL.md), addressing risky unknowns early. Use [architect](../architect/SKILL.md) when an unresolved design choice warrants it.
3. Establish a useful baseline before changing behavior. Use existing checks or build the smallest useful [tool](../principle-build-the-lever/SKILL.md); avoid elaborate infrastructure for a simple task.
4. Work one hypothesis at a time: change, observe, keep or revise. Revert only your failed experiment, preserving unrelated work.
5. For a long or unattended run, use [show-me-your-work](../show-me-your-work/SKILL.md) to record consequential choices and evidence in an appropriate location.
6. Verify the whole result against the goal and report verified outcomes, incomplete checks, and remaining work.

Proceed on authorized work without unnecessary permission questions. A request for a plan ends at the plan. Ask only for material missing input or actions outside authorization; continue independent work while waiting.

Delegation is optional and requires available authorized tools and separable ownership. Review actual artifacts from any delegated work. No fixed models, poteto-mode, arena, or mandatory human checkpoint is required.
