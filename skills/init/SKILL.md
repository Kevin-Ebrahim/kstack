# Init

Capture product facts that future work should preserve. This skill writes product context; it does not scaffold an application, design an identity, or configure a command runtime.

## Find the authority

Locate existing PRODUCT.md or equivalent product documentation, including parent/child app boundaries. Update the relevant authority rather than creating competing records. Preserve unrelated content and existing confirmed facts.

Inspect the brief, project docs, routes, workflows, roles, configuration, assets, and actual product claims. Determine platform and stack from evidence instead of assuming that an undocumented project is web-based.

## Resolve material gaps

Focus questions on who uses the product, what it enables, its distinctive mechanism, operating context, and constraints. Ask only where available evidence and the user's instructions do not answer a consequential choice. Do not impose an interview when the supplied brief is sufficient.

Keep repository observations, confirmed user intent, and uncertain inferences distinct. Record unresolved facts explicitly; do not manufacture pricing, customers, testimonials, capabilities, or strategic commitments. A recommended framework or workflow is not a user preference unless accepted or delegated.

## Write the record

Use the [product outline](references/product-outline.md) for relevant sections. Preserve the existing document structure where it works. For a new record, use the requested location or the appropriate project root's PRODUCT.md. Include evidence paths where they help future work distinguish facts from assumptions.

Keep palettes, component styling, session-specific page strategy, and tooling preferences out of the product record unless they are explicit durable constraints. Do not create DESIGN.md, hidden runtime configuration, live servers, or workflow defaults as side effects.

## Verify and finish

Read the result back, check source paths and factual claims, and inspect the diff for lost context. Summarize what was captured and what remains undecided. When this was a step in a larger authorized task, continue using the record; do not request approval again for settled work.
